Uses `PieChart` with one `Pie` (`innerRadius="62%"`, `outerRadius="88%"`, `paddingAngle={1}`, `cornerRadius={3}`, `strokeWidth={0}`). `chartData` holds five `{ device, users, fill }` records, where each `fill` is `var(--color-<device>)`. `chartConfig` defines `users` (label only) plus `phone`, `laptop`, `tablet`, `watch` and `other` colored `var(--blue)`, `var(--teal)`, `var(--indigo)`, `var(--orange)` and `var(--gray)`. The center text is a separate, absolutely positioned element over `ChartContainer` showing `total`, which is summed from `chartData` and formatted with `toLocaleString`. The tooltip uses `ChartTooltipContent` with `hideLabel` and `nameKey="device"`.

Replace `chartData` with your categories, giving each record a `fill` of `var(--color-<key>)`, and add a matching `chartConfig` entry with `label` and `color` for every key. Keep `dataKey` and `nameKey` on `Pie` pointed at your value and category fields, and update the tooltip's `nameKey` if you rename the category field. `total` is derived from `chartData`, so the center value updates automatically; change the `users` caption beneath it to describe your unit.

## Notes

The overlay uses `pointer-events-none` so hovering the center doesn't block the slices' tooltips. `accessibilityLayer` is set on `PieChart`, so the chart is focusable and arrow keys move between slices.
