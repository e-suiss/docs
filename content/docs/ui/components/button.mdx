`Button` wraps the Base UI Button primitive and renders a native `button` by default. It supports eight visual variants, five text sizes and five icon-only sizes, and an optional `block` mode that fills the container width.

Use the `default` variant for the primary action in a view, `secondary`, `tinted` or `outline` for supporting actions, `ghost` and `plain` for low-emphasis actions, and `destructive` for actions that delete or remove. To join several buttons into one control, use Button Group.

## Usage

```tsx
import { Button } from "@/components/ui/button"
```

```tsx
<Button>Button</Button>
```

Mark icons with `data-icon="inline-start"` or `data-icon="inline-end"` to tighten the padding on that side. Icons without a size class are sized automatically.

Use an `icon` size, such as `icon` or `icon-sm`, for buttons that contain only an icon, and give them an `aria-label`.

To render a link or a router component with button styling, use the `render` prop from Base UI. `buttonVariants` is also exported if you need the classes on another element.

## Accessibility

- Renders a native `button`, so `Enter` and `Space` activate it.
- A disabled button is removed from the tab order.
- Icon-only buttons need an `aria-label`.
- Keyboard focus shows a focus ring; the `destructive` variant uses the danger color for it.
- `aria-invalid` adds a danger-colored border, and `aria-expanded` shows a selected background on `outline`, `ghost` and `plain` buttons that open menus or popovers.

## Notes

- Styling hook: `data-slot="button"`.
- Colors come from semantic tokens such as `bg-accent`, `bg-control`, `bg-accent-surface` and `bg-danger-surface`, each with hover, pressed and disabled states.
- The focus ring offset is set with `--focus-ring-offset`; groups and other containers override it.
