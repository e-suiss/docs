The block combines the `AppShell` pattern for admin navigation with a `SplitView`: `SplitViewList` lists users as `SplitViewItem` rows with a gradient `Avatar` and role, and `SplitViewDetail` shows the selected user. The detail has a header with a large avatar, a `ToggleGroup` that switches between Profile, Sessions, and Security, and content built from `ItemGroup`, `Item`, `ItemMedia`, `ItemContent`, `ItemTitle`, `ItemDescription`, `ItemActions`, and `ItemSeparator`. Profile includes a role `Select`; Sessions lists devices with Sign Out buttons; Security shows `Switch` rows and a password reset `Button`. Below `md:` the split view shows one column at a time, starting with the list.

## Usage

<Code lang="tsx" code={"import { UsersDetail } from \"@/components/blocks/users-detail\""} />

<Code lang="tsx" code={"<UsersDetail />"} />

Edit `users` (`name`, `email`, `role`, `status`, avatar `hue`), `roles`, and `initialSessions` at the top of the file. The selected user, the active tab, per-user role `overrides`, and the session list are held in `React.useState`; each local `SecurityToggle` keeps its own state and resets when the selected user changes. The session list is shared by every user in the sample, and the Department and Joined values are hard-coded. Connect the role change, session sign-outs, security switches, and Send Password Reset Link button to your user management API.

## Notes

The tab group has `aria-label="Section"`, the role `SelectTrigger` has `aria-label="Role"`, and each security `Switch` is labeled by a `label` through `htmlFor` and a `React.useId` id. Rows use `role="listitem"` inside the list role of `ItemGroup`. The detail title is visually hidden with `sr-only`. The `AppShellTrigger` sits in a wrapper hidden at `md:`, and the trigger renders nothing on mobile-width viewports. Detail and tab transitions are disabled with `motion-reduce:`.
