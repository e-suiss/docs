The block is wrapped in the `AppShell` pattern with an admin navigation. The header shows the title, a pending count, and a `Select` for the approval length. Each request row has a gradient `Avatar`, the requester, the time, the requested permission, the reason, and Deny and Approve `Button` actions; actions sit beside the text from `sm:` up and below it on smaller screens. After a decision, the row shows Approved or Denied and then collapses out of the list. When the queue is empty, an `Empty` composition (`EmptyHeader`, `EmptyMedia`, `EmptyTitle`, `EmptyContent`) offers a link to reset the sample.

<Code lang="tsx" code={"<RolesRequests />"} />

Replace `initialRequests` with your requests; each has a `name`, `permission`, `reason`, `time`, and an avatar `hue`. Requests (with an added `decision`) and the approval length are held in `React.useState`. The `decide` function records the decision and removes the row after 900 ms; call your API there and pass the selected `duration`. Requests are matched by `name`, so switch to a unique id for real data. Remove the Reset the sample link in production.

## Notes

The pending count uses `aria-live="polite"`, and the decision label uses `role="status"` so the outcome is announced. The `SelectTrigger` is labeled by the visible Approval length text through `aria-labelledby`. The collapse and empty-state animations are disabled with `motion-reduce:`.
