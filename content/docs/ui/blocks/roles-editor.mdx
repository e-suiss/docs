The block combines two patterns: `AppShell` provides the admin navigation, and inside it a `SplitView` places the roles in `SplitViewList` (as `SplitViewItem` rows with a permission count, plus a New Role `Button`) and the selected role in `SplitViewDetail`. The detail shows the role name, how many users have it, and permission groups built from `ItemGroup`, `Item`, `ItemContent`, `ItemTitle`, `ItemDescription`, `ItemActions`, and `ItemSeparator`, with a `Switch` for each permission. Revert and Save buttons appear only when there are unsaved changes. Below `md:` the split view shows one column at a time, starting with the list.

## Usage

<Code lang="tsx" code={"<RolesEditor />"} />

Edit `groups` for the permission groups (each permission has a `name` and `description`), `roles` for the role names, `members` for the user count per role, and `defaults` for each role's initial switches. The `defaults` arrays are positional: each boolean maps to a permission in the order it appears across all groups, so keep their length in step with `groups`. The selected role, the working `state`, and the saved `base` are held in `React.useState`; changes are detected by comparing the two. Replace the Save handler, which only copies `state` into `base`, with a call to your API, and give New Role a handler.

## Notes

Each permission name is a `label` tied to its `Switch` through `htmlFor` and a generated `id`. Permission rows use `role="listitem"` inside the list role of `ItemGroup`. The detail title is visually hidden with `sr-only`, while the list title is shown from `md:` up. The `AppShellTrigger` sits in a wrapper hidden at `md:`, and the trigger renders nothing on mobile-width viewports. The detail's entry animation is disabled with `motion-reduce:`.
