---
title: Guarantees
description: The invariants Access holds. Breaking one is an implementation bug; the architecture changes to keep it, never the invariant.
eyebrow: Access
---

<Callout type="note">
These statements summarize the semantic invariants (INV-1 to INV-31) of the Access specification, which is in active design. The specification also defines ecosystem, experience, protocol, security and technical invariants.
</Callout>

## Where authority comes from

- **Access only ever derives authority from a Grant.** Positive authority exists only as a Grant lineage rooted at an AuthorityAnchor. Claims, acceptances, restriction policies, identity, authentication, membership, credential possession and risk never produce it. *(INV-1)*
- **Access never treats identity as authority.** The only thing the identity plane can give the authority plane is a Claim. *(INV-12)*
- **Access never grants authority implicitly.** Break-glass, legal-order and emergency authority exist only as Grants given explicitly in advance, with requirements and a time limit, under the same Exercise discipline. There is no impersonation. *(INV-28)*
- **Access never gives anyone semantic privilege.** The hosting provider, first-party Suiss products and operators hold no authority they were not explicitly granted, and use the same contract as everyone else. *(INV-29)*

## How authority narrows

- **Access never lets authority grow along a chain.** A Grant is allowed only when the child is a subset of its parent. Effective authority is the intersection along the lineage, and every Exercise draws from every budget in it. *(INV-3)*
- **Access always ties a Grant and an Exercise to exactly one basis.** Another lineage cannot keep an invalid one alive, and on-behalf-of comes only from the declared capacity. *(INV-4)*
- **Access never expresses "allow unless".** The positive authority language has no negation. "Allow unless X" is a positive Grant plus a restriction. *(INV-7)*
- **Access always keeps its authority algebra decidable.** The algebra for positive authority, delegation and subset proofs is typed, closed and decidable. *(INV-8)*
- **Access only allows delegation when it is explicitly delegable.** Reserved actions are never covered by a wildcard or a namespace prefix. *(INV-9)*
- **Access never makes widening easier than narrowing.** Expanding authority may carry stricter requirements than narrowing it, never the reverse. *(INV-10)*
- **Access never lets holding mean using.** An Instance can use only what its Mandate allows. An anonymous actor holds nothing. *(INV-11)*

## Changes and revocation

- **Access only changes authority state through one path.** Apart from genesis, authority state changes only through the committed ALLOW of a meta-action Exercise. There is no other write path for admins, providers, products or operators. *(INV-2)*
- **Access never revives what was revoked.** Revocation, expiry, renunciation and Instance termination are terminal, and everything derived from them becomes invalid going forward. *(INV-5)*
- **Access always applies restrictions as an overlay.** Restrictions only deny or require. They never break a lineage, and removing one is an expansion. *(INV-6)*
- **Access never backdates.** Authority takes effect no earlier than its commit time. Revocation applies from the moment it is committed, and completed Exercises remain history. *(INV-23)*
- **Access never lets a re-qualification revive an old holding.** When a holder's qualification lapses, everything derived from that holding episode ends for good. *(INV-31)*

## Claims, trust and federation

- **Access never records a claim as truth.** It records an attributable assertion. A signature proves authorship, not accuracy. *(INV-14)*
- **Access only uses a claim for the use it was accepted for.** Acceptance for one use is never acceptance for another. *(INV-15)*
- **Access never makes a claim issuer a grantor.** Selecting who a Grant applies to is not granting. *(INV-16)*
- **Access never treats foreign authority as local.** A foreign identity binds an actor only. Foreign authority takes effect only within a bridging Grant rooted locally, with an Acceptance. *(INV-17)*
- **Access never owns another system's facts.** Every fact has one canonical owner. Domain truth, Work state and effects are consumed as claims or opaque references. *(INV-25)*

## Decisions and records

- **Access never declares that an effect happened.** It decides and records an intent. Whether an effect took place is derived from attestations, and *unknown* is a first-class result. *(INV-18)*
- **Access only allows what is in the envelope.** An ALLOW is valid only for its intent envelope. A changed intent needs a new Exercise. *(INV-19)*
- **Access never treats approving as executing.** The authority to approve an action is not the authority to perform it. *(INV-20)*
- **Access never consumes a unit twice.** Committed ALLOWs that consume a unit are totally ordered and never exceed capacity. *(INV-21)*
- **Access always records the basis of a relied-upon ALLOW.** Every such decision is a durable, attributable record that lists the state it was based on. *(INV-22)*
- **Access always reaches the same decision from the same inputs.** Two compliant evaluators with the same records, claims, policies, time and intent produce the same Decision. *(INV-27)*
- **Access never rewrites history.** The existence, attribution, lineage, digest and time of a record cannot be deleted or rewritten. *(INV-30)*

## Failure and time

- **Access always fails closed.** A missing anchor, an unverifiable claim, unreachable state, an unclear federation status or a stale basis produces DENY or REQUIRE_ACTION, never ALLOW. A rate limiter, risk engine or cache failure never turns into ALLOW. *(INV-26)*
- **Access never relies on a signal for safety.** Offline verification runs with bounded staleness under a declared ValidityContract. Safety rests on expiry, version and checkpoints. *(INV-24)*

## Identity

- **Access always tracks Instance continuity.** An unbroken chain authenticated with the current key binding is the same Instance. A break is a new Instance, and recovery inherits no authority. *(INV-13)*
